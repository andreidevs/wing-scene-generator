# Разбор текстового запроса

Парсер (`lib/parse.ts`) локальный: без LLM, без интернета, без ключей. Один и тот же текст всегда даёт одну и ту же сцену.
Если на сервере задан ключ OpenRouter, появляется кнопка «Через LLM» (см. в конце): модель выдаёт то же намерение, дальше работает тот же код.
Слова живут в таблицах `lib/vocab.ts`. Чтобы научить парсер новому синониму, добавь его туда и строку в `lib/parse.test.ts`.

## Как он работает

1. Текст → нижний регистр, `ё` → `е`, режется на **предложения** (`. ; ! ?` и перевод строки).
2. Предложения про страницы (`USER 1`) и mute остаются целыми, остальные режутся на **фразы** по `:` и `,`.
3. Каждая фраза проходит правила по порядку, первое подходящее забирает её:

| # | Правило | Пример | Что получится |
|---|---|---|---|
| 1 | Страницы | «вокалы, мониторы и dca на USER 1» | USER 1: каналы вокала + шины + DCA |
| 2 | Mute | «вокалы не мьютить», «ничего не мьютить, кроме клика», «замьють плейбэк» | открыть / закрыть |
| 3 | Вручную | «включи фантом», «подними гейн», «выведи на выходы 1-2», «лимитер» | плашка «настрой вручную» |
| 4 | Уровни | «вокал −10 дб», «барабанщику кик погромче», «бас в ноль» | фейдер / посыл |
| 5 | Обработка | «HPF на вокале 150», «без компрессии на басе», «гейт на томы» | HPF / comp / gate |
| 6 | Эффекты и стрим | «реверб на барабаны», «дилей на сакс», «без стрима» | FX-шины, посылы, Stream |
| 7 | Мониторы | «вокалам мониторы», «барабанщику: кик и бас», «всем ушные мониторы» | мониторные миксы, in-ear |
| 8 | Шаблон состава | «сцена для рок-группы», «конференция», «подкаст» | типовой состав, если инструменты не названы |
| 9 | Служебное | «подпиши каналы», «назначь цвета», «сделай HPF», «пожалуйста» | ничего, это делается всегда |
| 10 | Инструменты | «4 вокала, 2 акустики, барабаны», «полная ударка», «клавиши стерео» | каналы |

4. Количество — число до 3 слов перед инструментом («4 вокальных микрофона», «две акустические гитары») или `x4` после.
   Без числа = 1, «оверы»/«тарелки» без числа = 2. «Стерео» у клавиш, плейбэка, DJ, SPD, аккордеона, зальных = 2 канала.
   «Полная ударка/полная установка» = кик, снейр, хэт, 3 тома, 2 овера; «барабаны» = кик, снейр, 2 овера.
5. Фраза, не подошедшая ни под одно правило, показывается как «не распознано», парсер её не угадывает.

## Мониторы

| Кому | Понимает | Шина | По умолчанию в миксе |
|---|---|---|---|
| вокалистам | вокалам, вокалистам, певцам, солисту | Bus 1 MON Vox | вокал, хор, толкбэк |
| барабанщику | барабанщику, ударнику, драммеру | Bus 2 MON Drum | кик, снейр, бас, перкуссия, клик, толкбэк |
| басисту | басисту | Bus 3 MON Bass | бас, кик, вокал, толкбэк |
| гитаристу | гитаристу, гитаристам | Bus 4 MON Gtr | гитары, акустика, вокал, толкбэк |
| клавишнику | клавишнику, пианисту, органисту | Bus 5 MON Keys | клавиши, аккордеон, вокал, толкбэк |
| духовым | духовым, саксофонисту, трубачу, тромбонисту, флейтисту | Bus 6 MON Brass | духовые, вокал, толкбэк |
| струнным | скрипачу, виолончелисту, струнным | Bus 7 MON Str | струнные, вокал, толкбэк |

**In-ear.** «ушные», «в уши», «in-ear», «IEM», «наушники» делают микс ушным: стерео-шина «IEM …», в неё идут возвраты реверба и дилея (−18 dB) и зальные микрофоны.
«Напольный монитор», «wedge» — моно. «Всем ушные мониторы» — каждому музыканту ушной микс; «все мониторы in-ear» — все объявленные миксы ушные.
«Мониторы всем» создаёт микс каждому музыкальному семейству из сцены.

«Барабанщику кик и снейр» задаёт состав явно. «Мониторы басисту» без состава берёт столбец «по умолчанию».
Список после двоеточия продолжает микс: «барабанщику: кик, снейр и бас».

## Эффекты

| Что | Понимает | Шина | FX |
|---|---|---|---|
| реверб вокала | реверб, ревер, холл, hall, plate (без барабанов) | Bus 13 Vocal Reverb → Main | FX1 V-REV |
| реверб барабанов | реверб + барабаны/томы/снейр | Bus 14 Drum Rev → Main | FX2 ROOM |
| дилей | дилей, delay, эхо, задержка | Bus 15 Delay → Main | FX3 ST-DL |

По умолчанию в реверб вокала идут вокал, хор, акустика, духовые и струнные, в реверб барабанов — снейр, томы и перкуссия, в дилей — вокал.
Если инструмент назван явно («реверб на гитару», «дилей на сакс»), посыл добавляется и ему.

## Уровни

По умолчанию всё на −18 dB: фейдеры каналов, посылы и фейдеры шин.

| Пишешь | dB |
|---|---|
| «−10», «−10 дб», «10 db» | как написано (от −60 до +10) |
| «погромче» | −12 |
| «намного громче» | −6 |
| «потише» | −24 |
| «еле слышно», «чуть-чуть» | −40 |
| «в ноль», «на ноль», «unity» | 0 |

Куда идёт уровень: «барабанщику/басисту…» — посыл в этот монитор (и источник добавляется в микс), «в реверб/дилей» — посыл в FX, «в стрим» — посыл в Stream, иначе — фейдер канала.
«Всё/все» = все каналы сцены.

## Обработка

| Пишешь | Результат |
|---|---|
| «HPF на вокале 150», «фильтр на басе 40 гц» | частота HPF |
| «компрессор на акустику», «компрессию на вокалах и барабанах» | comp вкл |
| «без компрессии на басе», «выключи компрессор на гитаре» | comp выкл |
| «гейт на томы», «без гейта на бочке» | gate вкл/выкл |

Без указания инструмента («сделай HPF», «компрессию») действуют пресеты.

## Шаблоны составов

Если в запросе нет ни одного инструмента, а есть формация — берётся типовой состав (с мониторами и FX), его можно править в таблице:
Рок-группа, Поп/кавер-группа (in-ear, клик, плейбэк), Джаз-трио, Джаз-квартет, Акустический дуэт, Акустическое трио, Церковь (in-ear, стрим),
Конференция (стрим), Подкаст (стрим), DJ-сет, Свадьба/корпоратив, Караоке, Струнный квартет, Духовой оркестр/брасс-бэнд, Хор, Театр.
Как только названы инструменты («рок-группа: 3 гитары, бас, барабаны»), шаблон не используется.

## Mute, страницы, стрим

- Все каналы в mute. «Вокалы не мьютить» открывает вокалы, «ничего не мьютить» — всё, «ничего не мьютить, кроме клика» — всё, кроме клика, «замьють плейбэк» — закрыть явно.
- Страницы стандартные. «… на USER 1 / USER 2» заполняет пользовательскую страницу: названные инструменты (или «все каналы»), плюс «мониторы/шины» и «dca», если упомянуты.
- «Стрим», «трансляция», «запись» → шина Stream (Bus 16); «без стрима» — нет.

## Что генератор специально не меняет

Парсер узнаёт эти слова и пишет «настрой вручную»: фантом (48V), гейн/трим, EQ, панорама, выходы/роутинг/USB/Dante/MADI, подгруппы,
лимитер/де-эссер/сайдчейн, матрицы/сабы/фронтфиллы, параметры эффектов (время реверба, pre-delay), автомикс/кью-лист, mute-группы.

## LLM через OpenRouter (необязательно)

- Серверный ключ: `OPENROUTER_API_KEY` в окружении (Vercel → Environment Variables, локально `.env.local`). Тогда кнопка «Через LLM» есть у всех, запрос идёт через `app/api/llm`, ключ в браузер не попадает. Без ключа кнопки нет, работает только локальный парсер.
- Модель — `xiaomi/mimo-v2.6-flash`, резервная — `deepseek/deepseek-v4.1-flash-1017`; меняется переменной `OPENROUTER_MODEL`. Выбраны прогоном `npm run eval` по 51 сцене и 10 моделям (≈ $0.08–0.15 за 1000 запросов).
- Промпт строгий: «заполняй только то, что сказано», правила счёта и адресатов как у парсера, примеры вход → JSON (сгенерированы парсером на фразах вне проверочного набора).
- **Голосование.** Ответ модели сравнивается с локальным парсером по итоговой сцене. Совпали — готово (1 вызов). Не совпали — ещё 2 вызова параллельно, побеждает сцена с большинством голосов из {парсер, 3 ответа модели}. Случайный сбой модели так перекрывается.
- Таймаут 20 с на вызов, при обрыве — повтор на резервной модели; если OpenRouter недоступен, возвращается сцена парсера.

## Проверка качества

- `scripts/eval-cases.ts` — 36 сцен основного набора и 15 контрольных (контрольные не использовались для настройки).
- `npm run eval -- --parser [--holdout]` — локальный парсер (бесплатно).
- `npm run eval -- --models <id,id> [--vote] [--holdout] [--verbose]` — модели OpenRouter, ключ из `.env.local`.
- Сравнение идёт по итоговой сцене (каналы, миксы, посылы, уровни, mute, обработка, страницы), а не по JSON.
- Парсер на обоих наборах закреплён тестом (`lib/parse-eval.test.ts`, входит в `npm test`).

Результаты (2026-11): парсер 36/36 + 15/15; `mimo-v2.6-flash` один вызов 33–36/36, с голосованием 36/36 + 15/15 во всех прогонах; прежняя `mistral-nemo` со старым промптом — 0/36.
