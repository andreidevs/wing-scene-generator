# WING Scene Generator

Текст на русском → локальный парсер распознаёт намерение → детерминированный код раскладывает каналы → патч проверенного baseline `.snap` → diff + отчёт → проверка в WING EDIT → загрузка на пульт.

Работает полностью офлайн, без API-ключей. Парсер на правилах (`lib/parse.ts`) извлекает из текста только намерение (`lib/intent.ts`):
- источники и их количество («4 вокала», «две акустики», «барабаны», «бочка, малый, 2 тома, оверы»…);
- мониторы и их состав («вокалам мониторы», «барабанщику: кик, снейр и бас»);
- реверб (вокал/барабаны), стрим («стриму стерео-микс», «без стрима»);
- уровни («вокал −10 дб», «барабанщику кик погромче», «всё в стрим −6»);
- mute («вокалы не мьютить», «ничего не мьютить»);
- страницы («вокалы, мониторы и dca на USER 1»).

Полный список понимаемых слов и фраз: [docs/parser.md](docs/parser.md). Словарь — `lib/vocab.ts`: 31 тип источника, мониторы для 7 музыкантов (напольные и in-ear), 16 шаблонов составов, уровни, обработка, mute, страницы.

Необязательно: LLM через OpenRouter (`xiaomi/mimo-v2.6-flash`, доли цента за запрос) выдаёт то же намерение, что и парсер; ответ сверяется с парсером голосованием (см. [docs/parser.md](docs/parser.md)). Качество меряется `npm run eval`.
- На сервере: переменная `OPENROUTER_API_KEY` (локально в `.env.local`, на Vercel в Environment Variables) — кнопка «Через LLM» доступна всем посетителям, ключ не уходит в браузер. Поставь лимит кредитов на ключ в OpenRouter.

Деплой — Vercel (Next.js определяется автоматически). CI на GitHub Actions (`.github/workflows/ci.yml`): типы, линт, тесты, сборка.

Фрагменты, которые парсер не понял, показываются в UI, а не угадываются. Номера каналов, HPF, цвета, иконки, comp/gate, посылы и DCA задаёт код (`lib/presets.ts`, `lib/scene.ts`). В таблице каналы можно добавлять, удалять и править.

## Что делает генератор

Берёт baseline-снапшот из WING EDIT (подойдёт и чистая сцена) и меняет только поля из allowlist (`lib/wing.ts`):

| Что | Как |
|---|---|
| Каналы | `clink=false` (свои имя/цвет, не из источника), имя, цвет, иконка, HPF (вкл + частота), gate, компрессор, фейдер, посылы (on/уровень/PRE-POST), DCA через `tags` |
| Шины ролей | имя, цвет, mono/stereo, фейдер, FX-инсерт, назначение FX-возвратов в Main 1 |
| FX | целые блоки V-REV (FX1) и ROOM (FX2), снятые с рабочего шоу |
| DCA | имя, цвет, фейдер 0 dB для используемых групп |
| Mute | все 40 каналов в mute; открываются только каналы, которые явно названы в запросе («не мьють вокал») или открыты в таблице |
| Страницы | по умолчанию стандартные: страницы «CH a-b» = каналы a…b во всех секциях (L, C, R, Compact, Rack, WING Edit). По запросу в чате — USER 1 / USER 2 с каналами, шинами и DCA сцены |

Раскладка шин (`BUS_LAYOUT` в `lib/presets.ts`):

| Роль | Шина | Тип | Посыл |
|---|---|---|---|
| Монитор вокала | Bus 1 MON Vox | mono | PRE |
| Монитор барабанщика | Bus 2 MON Drum | mono | PRE |
| Реверб вокала | Bus 13 Vocal Reverb, FX1 V-REV | stereo → Main 1 | POST |
| Реверб барабанов | Bus 14 Drum Rev, FX2 ROOM | stereo → Main 1 | POST |
| Стрим | Bus 16 Stream | stereo | POST |

Уровни по умолчанию −18 dB (фейдеры каналов и шин, посылы). Парсер меняет их, только если в тексте явно сказано.

Цвета (12 цветов WING) по группам: вокалы — пурпурный (mauve), барабаны — красный (оверы, перкуссия, SPD — оранжевый), бас — тёмно-синий, гитары — зелёный, клавиши — бирюзовый, струнные/духовые — жёлтый, плейбэк/FX/атмосфера/клик — серо-синий, речь и толкбэк — коралловый. Шины и DCA — цвет своей группы, FX-шины и стрим — серо-синий.

Иконки (пикер WING: сотни = категория, 5 в ряд; сверено с рабочим шоу): Kick 201, Snare 202, HiHat 205, Toms 206/207/208/209 (H/M/L/F по порядку), OH 210, Perc 216, SPD 223, Click 222, Bass 300, Ac 304, Gtr 306, Violin 309, Cello 310, Sax 312, Tbn/Horn 313, Tpt 314, Harp 315, Accordion 316, Harmonica 317, Flute 318, Winds 319, Keys 408, Talkback 100, Vox 101, MC 102, Amb 109, BVox/Choir 112, Playback 605, DJ 611. Шины: мониторы — иконка инструмента (MON Vox — ухо 601), in-ear — наушники 602, FX — 6, Stream — 605.

**Не трогает никогда:** входы (`in.conn`), гейн, фантом, выходы (`io.out`), Main, карты, настройки консоли. Контрольные счётчики считаются по реальному diff baseline ↔ результат и должны быть 0. Выходы и USB для шин настраиваются вручную, отчёт перечисляет, что куда сейчас выведено.

Формат файла: [docs/snap-format.md](docs/snap-format.md).

## Команды

```bash
npm install
npm test                                  # tsx --test lib/*.test.ts
npm run inspect -- fixtures/baseline.snap # структура snapshot
npm run inspect -- fixtures/baseline.snap --grep "ch/#/name"
npm run example                           # пример из ТЗ → examples/*.snap + отчёт, для проверки в WING EDIT
npm run dev                               # http://localhost:3000 (cp .env.example .env.local для LLM)
npm run build                             # продакшн-сборка, как на Vercel
```

Модель задаётся в одном месте: `PLAN_MODEL` в `lib/plan.ts`.
